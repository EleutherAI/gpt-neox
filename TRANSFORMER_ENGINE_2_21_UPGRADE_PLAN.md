# Upgrade GPT-NeoX from Transformer Engine 1.12 to 2.21.0

Prepared against GPT-NeoX `1212fee` on 2026-11-27. The target is NVIDIA's released **2.21.0** PyTorch integration. This plan covers the optional host install, the Hopper and B200 images, training and inference through NeoX, and existing checkpoints. Section 3 records the dedicated image and its H100 baseline. Training, checkpoint compatibility and qualification on other GPU types are open. [NVIDIA 2.21.0 release](https://github.com/NVIDIA/TransformerEngine/releases/tag/v2.21.0) · [PyPI release](https://pypi.org/project/transformer-engine/2.21.0/)

## Decisions that determine the migration

| Decision | Proposed treatment |
| --- | --- |
| Which stack to qualify first | Use one dedicated Docker image, `gpt-neox:te-2.21-test`, for the 2.21 migration tests. Bind-mount the checkout so every candidate revision runs against the same environment. Use the existing 1.12 image to generate reference results. Port the qualified setup to the other images afterwards. |
| Existing FP16/BF16 configs | Keep the existing model, precision, parameter layouts and bias semantics. The shipped 1.3B TE example enables TE MHA and fused LayerNormMLP in FP16. It explicitly disables FP8. Run it and a separate FP8 configuration. |
| Existing FP8 configs | Keep explicit delayed scaling and the current amax settings. The default `te_fp8_wgrad: true` has a direct migration. When FP8 is active, `false` requests high-precision weight gradients only. TE 2.21 delayed scaling cannot express that choice. Give this configuration an early, actionable error and document the legacy-image option. |
| Checkpoint compatibility | Treat loading actual 1.12 weights, optimizer state and FP8 histories as a release criterion. Preserve an immutable last-known-good 1.12 checkpoint and image. A successful model-weight comparison alone cannot establish resumability. |
| New TE capabilities | Qualify the currently exposed NeoX features first. Evaluate new recipes, attention variants and compilation under separate opt-ins, with numerical and hardware criteria below. |

### FP8 precision and autocast

- [ ] Replace the recipe subclass with a helper that constructs a stock `DelayedScaling`. Keep NeoXArgs and the live process group **outside** the recipe. TE 2.21 serializes the recipe in FP8 extra state. The existing subclass stores both `neox_args` and `tp_group`, risking a non-serializable distributed object and a NeoX-specific type in the checkpoint. Construct the recipe after model-parallel initialization and open a fresh context per forward. [2.21 checkpoint implementation](https://github.com/NVIDIA/TransformerEngine/blob/v2.21.0/transformer_engine/pytorch/module/base.py)
- [ ] Remove `override_linear_precision=(False, False, ...)` from construction. In 1.12 the third member selected higher-precision **wgrad only**. In 2.21 the argument is absent and `DelayedScaling` only accepts `backward_override=None`. Keep the existing `te_fp8_wgrad: true` default. Reject `false` only where delayed FP8 is active, with the requested precision and available options in the message. Test that a dormant FP8 setting still parses in an FP16/BF16 run. A different recipe or a whole-backward override changes the experiment. The old `interval` keyword was also removed in 2.2. NeoX does not pass it. [1.12 recipe](https://github.com/NVIDIA/TransformerEngine/blob/v1.12/transformer_engine/common/recipe/__init__.py) · [2.21 recipe](https://github.com/NVIDIA/TransformerEngine/blob/v2.21.0/transformer_engine/common/recipe/__init__.py)
- [ ] Migrate `fp8_autocast(enabled=True, fp8_recipe=..., fp8_group=...)` to `te.autocast(enabled=True, recipe=..., amax_reduction_group=...)`. The old name became deprecated in 2.9. Preserve the actual TP group, explicit E4M3/HYBRID format, margin, amax algorithm and history length. NeoX defaults to history **1** and `most_recent`. TE delayed-scaling defaults are **1024** and `max`. Use explicit MHA/DPA flags when FP8 MHA is requested. Check the effective recipe at runtime, including on Blackwell where the hardware default can differ. [2.9 release](https://github.com/NVIDIA/TransformerEngine/releases/tag/v2.9) · [2.21 autocast](https://github.com/NVIDIA/TransformerEngine/blob/v2.21.0/transformer_engine/pytorch/quantization.py) · [2.0 default change](https://github.com/NVIDIA/TransformerEngine/releases/tag/v2.0)
- [ ] Preserve context scope. The `te_fp8_mha` flag currently wraps the **whole transformer block forward**, so other TE modules in that block can run in FP8. `te_mha` alone uses model precision. Run combinations with and without fused MLP and TE linears and check the effective dtypes. Move the branch-local `nullcontext` import out of `ParallelTransformerLayer.forward` (the module already imports it). The local import shadows it on the FP8 path. Inspect uses of `self.eval` as a boolean and exercise actual training, evaluation and backward grad mode. Check accumulation and DeeperSpeed recomputation for double amax updates or diverging dropout RNG.
- [ ] Check FP8 GEMM alignment and capability, then qualify **FP8 attention** separately. TE 2.16 removed the original delayed-scaling attention implementation and the f16_max512 fused backend. Delayed scaling for linear layers remains available. TE 2.20.2 removed `NVTE_FUSED_ATTN_BACKEND`. Inspect site launch scripts for that override. Record the selected backend and precision for each MHA case using `NVTE_DEBUG=1 NVTE_DEBUG_LEVEL=2` or a profiler. Include rotary and non-rotary cases because TE may keep the QKV output in higher precision for RoPE. Require evidence that the claimed FP8 attention training path executed. [2.16 removals](https://github.com/NVIDIA/TransformerEngine/releases/tag/v2.16) · [2.20.2 changes](https://github.com/NVIDIA/TransformerEngine/releases/tag/v2.20.2) · [2.21 backend selection](https://github.com/NVIDIA/TransformerEngine/blob/v2.21.0/transformer_engine/pytorch/attention/dot_product_attention/utils.py)

## 5. Migrate checkpoints and verify Hugging Face export

- [ ] Inventory state keys **per enabled module** and TP/PP shard from the fixtures. Check `attention.qkv.*`, `attention.proj.*`, `mlp.fc1_*`, `mlp.fc2_*`, `mlp.layer_norm_*`, standalone norm keys and `_extra_state`. Distinguish trainable weights, omitted biases, optimizer shards and TE quantization metadata. Capture a mixed configuration such as TE attention with a native MLP.
- [ ] Exercise the default loader first. In normal training TE 1.12 typically writes `_extra_state` as `io.BytesIO`, even when its payload is empty. TE 2.21 emits an empty byte tensor for a non-FP8 module and serializes stateful delayed-scaling metadata for FP8. Its loader refuses legacy byte streams and stateful pickles by default. This matters for **both** legacy migration and 2.21 delayed-scaling resume. An outer DeeperSpeed `torch.load` succeeding does not settle the inner TE load. The current NeoX packer uses contiguous tokens. Add padded offsets, context parallelism or per-sequence policies only with a corresponding data contract and isolation tests. [2.21 release](https://github.com/NVIDIA/TransformerEngine/releases/tag/v2.21.0) |
| Compilation and FP8 weight caching | 2.21 expands `torch.compile(fullgraph=True)` coverage for specific attention/linear paths. NeoX currently overwrites `NVTE_TORCH_COMPILE=0` on import. That variable controls TE's **internal** fusions. Preserve the eager baseline, then honor an explicit operator setting and benchmark internal fusions and external model compilation separately. Test dynamic shapes, warm-up cost and recomputation. Before enabling `is_first_microbatch` weight caching, wire it to the true accumulation/optimizer-step boundary and test for stale weights. [TE environment variables](https://github.com/NVIDIA/TransformerEngine/blob/v2.21.0/docs/envvars.rst) · [2.21 compilation coverage](https://github.com/NVIDIA/TransformerEngine/releases/tag/v2.21.0) |

TE logit softcapping acts before softmax. Preserve the existing validation for that combination. [2.21 MHA](https://github.com/NVIDIA/TransformerEngine/blob/v2.21.0/transformer_engine/pytorch/attention/multi_head_attention.py) |
